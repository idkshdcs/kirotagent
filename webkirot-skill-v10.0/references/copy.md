# UI Copy and Product Writing

Load when writing or revising headings, product descriptions, onboarding, navigation labels, buttons, empty states, validation, notifications, errors, help text, or marketing content.

## Write for the user's task

- Identify the page goal, audience, product facts, and desired tone from the brief or existing project. Do not ask again when this is already clear.
- Explain what the product does and what the visitor can do next. Prefer specific, concrete wording over generic claims, hype, filler, or repeated slogans.
- Give each section one job. Avoid repeating the same benefit in multiple headings or cards.
- Make labels short and consistent. Buttons should name an action, such as “Create project”, “Save changes”, or “Copy key”. Avoid vague labels such as “Submit” when a clearer action fits.
- Use the same terms for the same concepts across navigation, forms, dialogs, and messages.

## Truth and localization

- Use only facts supplied by the user, project data, or sources that were actually verified. Never invent customers, testimonials, metrics, guarantees, certifications, prices, availability, or integrations.
- If facts are missing, omit the claim or use a clearly marked placeholder for the owner to replace. Do not invent realistic-looking phone numbers, addresses, or contact information.
- Write in the language appropriate to the site's audience, not automatically the language of the person prompting the agent. Preserve the user's requested locale and natural phrasing.
- Keep error messages actionable and safe: explain what happened at a useful level, what the user can do next, and avoid exposing secrets or stack traces.
- Empty states should explain why the area is empty and offer a relevant next action when one exists. Success messages should appear only after the underlying action succeeds.

## Editing existing copy

Preserve established terminology and brand voice unless asked to change them. For a narrow copy edit, change only the requested text and nearby wording needed for clarity. Do not rewrite the entire page as a side effect.
